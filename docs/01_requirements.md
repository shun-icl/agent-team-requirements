## 1. 背景・目的

### 背景

当社はニッチ業界（歯科・医療・介護・中小企業）向けに、コンサルティング・人材紹介・制作・DX支援等を提供している。現在、代表がフロント業務（営業・提案・顧客対応）を担い、バックエンド業務は外注・テンプレ化で効率化を図っている。

しかし、以下の課題が顕在化している（仮説）：

- **属人化**: 代表の稼働がボトルネックとなり、スケールに限界
- **情報分散**: 案件情報、顧客情報、ナレッジが複数ツールに散在
- **可視化不足**: 事業KPIがリアルタイムで追えない
- **標準化不足**: 納品プロセスが案件ごとに異なり、品質にばらつき

### 目的

本要件定義書は、上記課題を解決し、**エージェントチーム（AI + 人間）が継続的に改善・実装できる事業基盤**を構築するための要件を定義する。

## 3. スコープ（やること/やらないこと）

### やること（In Scope）

| 領域 | 対象 |
|------|------|
| 業務プロセス | リード獲得→商談→契約→納品→継続の仕組み化 |
| データ基盤 | KPI可視化、案件/顧客データの一元管理 |
| ナレッジ管理 | テンプレート・成果物・ノウハウの整備 |
| 自動化 | 定型業務の自動化（請求、レポート、通知等） |
| 外注管理 | 品質管理、成果物管理、コミュニケーション標準化 |

### やらないこと（Out of Scope）

| 対象外 | 理由 |
|--------|------|
| 新規サービス開発 | 既存サービスの最適化を優先 |
| 大規模システム導入 | 既存ツール（Sheets/Drive/GAS等）を活用 |
| フロント業務の代替 | 代表の営業・提案は維持（エージェントは支援のみ） |
| クライアント向けシステム開発 | 社内基盤が対象 |

```

  ↓ 紹介/SNS/HP問い合わせ等
```

## 5. あるべき姿（To-Be）

### ビジョン

**「代表が営業・提案に集中できる状態で、月商1,000万円・粗利率70%を維持しながら、品質を落とさずスケールできる事業基盤」**

### To-Be状態の定義

| 観点 | あるべき状態 |
|------|-------------|
| 代表の役割 | 営業・提案・重要意思決定に集中。定型業務からの解放 |
| 情報管理 | 全案件情報がSheetsに一元化。検索・参照が即座に可能 |
| KPI可視化 | 週次でダッシュボード更新。主要指標が10秒で確認可能 |
| 納品プロセス | サービス別にテンプレート化。品質チェックリスト運用 |
| ナレッジ | 成果物・テンプレがDriveで整理。再利用率向上 |
| 外注管理 | 成果物定義・進捗・品質が可視化。コミュニケーション標準化 |
| 自動化 | 請求書発行、リマインド、レポート生成がGASで自動化 |

## 8. 非機能要件

### 8.1 セキュリティ/アクセス制御/監査ログ

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| SEC-01 | 情報資産へのアクセスは最小権限の原則に基づく | P0 |
| SEC-02 | 外注/パートナーは必要なフォルダ/DBのみにアクセス可能 | P0 |
| SEC-03 | 重要操作（削除・エクスポート等）はログが残る | P1 |
| SEC-04 | 退職/契約終了時の権限削除フローがある | P0 |

### 8.2 個人情報

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| PII-01 | 候補者情報（人材紹介）の取り扱いポリシーが定義されている | P0 |
| PII-02 | クライアント内部情報の取り扱いポリシーが定義されている | P0 |
| PII-03 | 個人情報を含むデータは暗号化 or アクセス制限される | P1 |
| PII-04 | 個人情報の保持期間・削除ルールが定義されている | P1 |

### 8.3 可用性/バックアップ/権限設計

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| AVL-01 | 重要データは自動バックアップされる | P1 |
| AVL-02 | ツール障害時の代替手段が定義されている | P2 |
| AVL-03 | 権限マトリクス（誰が何にアクセスできるか）が文書化されている | P1 |

## 10. リスクと対策

| # | リスク | 影響度 | 発生可能性 | 対策 |
|---|--------|--------|-----------|------|
| 1 | ツール乱立による情報分散 | 高 | 中 | 役割分担を明確化（Sheets=データ管理、Drive=成果物・テンプレート、GAS=自動化） |
| 2 | 外注の品質ばらつき | 中 | 高 | チェックリスト運用、成果物レビュープロセス |
| 3 | 代表不在時の業務停滞 | 高 | 中 | 標準フロー整備、権限委譲範囲の明確化 |
| 4 | 個人情報漏洩 | 高 | 低 | アクセス制御、ポリシー整備、定期監査 |
| 5 | エージェント（AI）の誤動作 | 中 | 中 | 重要操作は人間承認、ログ監視、段階的導入 |
| 6 | 導入コストの肥大化 | 中 | 中 | MVP優先、既存Google Workspace活用、段階的拡張 |
