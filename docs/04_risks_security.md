# 04. リスク/セキュリティ/個人情報方針

> **目的**: 事業運営におけるリスク管理、情報セキュリティ、個人情報取り扱いの方針を定義
> **対象者**: 代表、社内運用担当、外注/パートナー、エージェントチーム
> **更新頻度**: 四半期レビュー or 重大インシデント発生時

## 2. 情報セキュリティ方針

### 2.1 基本方針

1. **最小権限の原則**: 業務に必要な最小限の権限のみを付与する
2. **責任分離**: 重要な操作は複数人のチェックを経る
3. **監査可能性**: 重要な操作はログに記録し、追跡可能にする
4. **定期見直し**: 権限設定・セキュリティ体制を定期的に見直す

### 2.2 アクセス権限設計

#### 権限レベル定義

| レベル | 名称 | 権限範囲 | 対象者 |
|--------|------|----------|--------|
| L1 | 管理者 | 全リソースへのフルアクセス | 代表 |
| L2 | 運用者 | 担当業務に関するリソースへの編集権限 | 社内運用担当 |
| L3 | 外注 | 担当案件のみへの限定アクセス | 外注/パートナー |
| L4 | 閲覧者 | 特定リソースの閲覧のみ | 一時的な関係者 |

#### リソース別権限マトリクス

| リソース | 代表(L1) | 運用担当(L2) | 外注(L3) | 備考 |
|----------|----------|--------------|----------|------|
| 顧客マスタDB | フル | 編集 | なし | 顧客情報は外注に非公開 |
| 案件DB | フル | 編集 | 担当案件のみ閲覧 | |
| リードDB | フル | 編集 | なし | |
| 請求管理シート | フル | 編集 | なし | 金額情報は限定公開 |
| 成果物フォルダ | フル | 編集 | 担当案件のみ編集 | |
| ナレッジDB | フル | 編集 | 閲覧 | |
| 契約書フォルダ | フル | 閲覧 | なし | 契約情報は厳格管理 |

### 2.3 アカウント管理

#### 入社/参画時

| # | アクション | 担当 | タイミング |
|---|-----------|------|-----------|
| 1 | Googleアカウント発行 or 招待 | 代表 | 参画決定後 |
| 2 | Notion ワークスペース招待 | 代表/運用 | 参画初日 |
| 3 | 必要フォルダへの権限付与 | 代表/運用 | 参画初日 |
| 4 | Slackワークスペース招待 | 代表/運用 | 参画初日 |
| 5 | セキュリティガイドラインの共有・同意取得 | 代表 | 参画初日 |

#### 退職/契約終了時

| # | アクション | 担当 | タイミング |
|---|-----------|------|-----------|
| 1 | 全ツールからの権限削除 | 代表 | 最終日 |
| 2 | 共有パスワードの変更（該当する場合） | 代表 | 最終日 |
| 3 | 成果物・データの引継ぎ確認 | 運用 | 最終日前 |
| 4 | 貸与機器・アカウントの返却確認 | 代表 | 最終日 |

### 2.4 パスワード/認証ポリシー

| 項目 | ルール |
|------|--------|
| パスワード強度 | 12文字以上、英数字記号混合を推奨 |
| 2要素認証 | Google、Notion等主要サービスで有効化必須 |
| 共有アカウント | 原則禁止。やむを得ない場合は管理台帳で管理 |
| パスワード共有 | 直接共有禁止。必要な場合はパスワードマネージャー経由 |

### 2.5 バックアップ方針

| 対象 | 方法 | 頻度 | 保持期間 |
|------|------|------|----------|
| Notion | 自動エクスポート（要確認） | 週次 | 3ヶ月 |
| Sheets | 版履歴（Google自動） | 自動 | 無期限 |
| Drive | バージョン履歴（Google自動） | 自動 | 無期限 |
| 重要ファイル | ローカルバックアップ | 月次 | 1年 |

## 3. 個人情報取り扱い方針

### 3.1 取り扱う個人情報の種類

| 種類 | 内容 | 機密度 | 保管場所 |
|------|------|--------|----------|
| 候補者情報 | 履歴書、職務経歴書、連絡先、面談記録 | 高 | 要確認 |
| クライアント担当者情報 | 氏名、連絡先、役職 | 中 | Notion顧客DB |
| 従業員/外注情報 | 氏名、連絡先、報酬情報 | 中 | 要確認 |
| 医療・介護関連情報 | クライアント施設の従業員/患者情報（取り扱う場合） | 最高 | 要確認 |

### 3.2 個人情報取り扱い原則

1. **収集制限**: 業務に必要な範囲のみ収集
2. **利用目的の明示**: 収集時に利用目的を明確に伝える
3. **第三者提供の制限**: 本人同意なく第三者に提供しない
4. **安全管理**: 適切な技術的・組織的対策を講じる
5. **保持期間の設定**: 必要な期間を超えて保持しない
6. **本人アクセス**: 開示・訂正・削除の要求に対応する

### 3.3 候補者情報の取り扱い（人材紹介業務）

| フェーズ | 取り扱いルール |
|----------|---------------|
| 収集 | プライバシーポリシーへの同意取得必須 |
| 保管 | アクセス権限を持つ者のみが閲覧可能な場所に保管 |
| 共有 | クライアントへの共有は候補者同意の範囲内 |
| 保持 | 紹介終了後○ヶ月で削除（要確認） |
| 削除 | 削除依頼には○営業日以内に対応（要確認） |

### 3.4 クライアント内部情報の取り扱い

| 情報種類 | 取り扱いルール |
|----------|---------------|
| 経営情報 | NDA締結、アクセス者限定、案件終了後は削除 or 返却 |
| 従業員情報 | 業務に必要な範囲のみ閲覧、外部持ち出し禁止 |
| 財務情報 | 厳格なアクセス制限、コピー禁止 |
| 医療情報 | 特別な取り扱い（医療法、個人情報保護法に準拠） |

### 3.5 インシデント対応

| インシデント | 対応手順 |
|-------------|----------|
| 情報漏洩（疑い含む） | 1. 即時報告（代表へ） 2. 影響範囲特定 3. 関係者への通知 4. 再発防止策 |
| 不正アクセス | 1. アカウント停止 2. パスワード変更 3. ログ確認 4. 原因究明 |
| データ紛失 | 1. 即時報告 2. バックアップからの復旧 3. 原因究明 |

## 4. 外注/パートナー管理

### 4.1 契約時のセキュリティ要件

| 項目 | 要件 |
|------|------|
| 秘密保持 | NDA締結必須 |
| 個人情報取り扱い | 個人情報取り扱い委託契約（該当する場合） |
| 成果物の権利 | 著作権等の帰属を明確化 |
| 再委託 | 原則禁止、必要な場合は事前承認 |
| 損害賠償 | 情報漏洩時の責任範囲を明確化 |

### 4.2 外注の独立リスク対策

| リスク | 対策 |
|--------|------|
| キーパートナーの離脱 | 複数パートナー体制、業務の標準化・文書化 |
| ノウハウの流出 | 成果物・ナレッジの社内蓄積、契約での権利確保 |
| 競合への流出 | 競業避止条項（法的有効性を考慮しつつ） |
| 品質の属人化 | チェックリスト、レビュープロセスの標準化 |

### 4.3 成果物管理

| 項目 | ルール |
|------|--------|
| 納品場所 | 指定のDriveフォルダに格納（外注個人のストレージに残さない） |
| 版管理 | ファイル名に版番号 or Driveのバージョン管理を使用 |
| 最終版の明示 | 「_final」等のサフィックス or ステータス管理 |
| 引継ぎ文書 | 設定値、手順書等を成果物に含める |

## 5. 生成AI（エージェント）利用ルール

### 5.1 利用可能な範囲

| 用途 | 可否 | 条件 |
|------|------|------|
| 社内文書作成支援 | ○ | 個人情報を含めない |
| コード生成 | ○ | セキュリティレビューを経る |
| データ分析 | ○ | 匿名化・集計データのみ |
| 顧客向け提案書作成 | ○ | 最終確認は人間が行う |
| 候補者情報の処理 | △ | 匿名化必須、ツールによる |
| 契約書作成 | △ | 法務確認必須 |
| 医療情報の処理 | × | 原則禁止 |

### 5.2 プロンプトインジェクション対策

| 対策 | 内容 |
|------|------|
| 入力検証 | ユーザー入力をそのままプロンプトに含めない |
| 権限分離 | AIの操作権限を最小限に設定 |
| 出力検証 | AI出力を信頼せず、重要操作前に人間が確認 |
| ログ監視 | AI操作のログを記録し、異常を検知 |

### 5.3 エージェントの操作権限

| 操作カテゴリ | 権限レベル | 承認要否 |
|-------------|-----------|----------|
| データ閲覧 | 許可 | 不要 |
| ドキュメント作成 | 許可 | 不要 |
| データ更新 | 条件付き許可 | 重要フィールドは要承認 |
| データ削除 | 制限 | 必ず人間承認 |
| 外部送信（メール等） | 制限 | 必ず人間承認 |
| 権限変更 | 禁止 | - |
| 決済・契約 | 禁止 | - |

### 5.4 段階的導入アプローチ

| Phase | 範囲 | 監視レベル |
|-------|------|-----------|
| 1 | 閲覧・分析のみ | 全操作ログ監視 |
| 2 | 文書作成・データ更新（承認付き） | 重要操作のみ監視 |
| 3 | 定型業務の自動化 | 例外検知のみ |
